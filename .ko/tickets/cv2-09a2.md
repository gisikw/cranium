# Per-profile saturation thresholds and context budgets

## Original scope
TurnInjector has hardcoded `@saturation_warn_threshold 50` and `@saturation_bucket_size 5` as module attrs. Original ask: move to Application.get_env.

## Revised scope
Moving to Application.get_env is still global. The actual need is **per-profile** parameterization because saturation curves differ by model:

- **Context window size** varies (Opus 200k, Gemma4 256k)
- **Effective ceiling** differs — a local model may degrade well before its nominal context limit
- **Warning thresholds** should reflect per-model quality curves, not a one-size-fits-all percentage

### Profile config additions
```yaml
profiles:
  exo:
    context_window: 200_000
    saturation_warn: 50
    saturation_critical: 80
  exo-local:
    context_window: 262_144
    saturation_warn: 40
    saturation_critical: 65
```

### Touch points
1. **Config.Profile struct** — add `context_window`, `saturation_warn`, `saturation_critical` fields (with sensible defaults)
2. **Config.resolve_profile/1** — surface new fields
3. **TurnAssembler** — pass profile saturation config into injection context
4. **Harness.compute_saturation/1** — use profile's `context_window` instead of global `max_context_tokens`
5. **TurnInjector.maybe_add_saturation/3** — use profile's warn/critical thresholds
6. **Global config.exs `:pipeline`** — keep `max_context_tokens` as fallback default only
