# MCP server for meta-tools — expose clear_context (and future meta-tools) to Claude Code backend via MCP. CC connects via --mcp-server flag, cranium handles tool calls internally. Required because CC manages its own tool loop and doesn't see cranium's tool definitions.

## Context

The clear_context tool was implemented (cv2-eb3a, cv2-fbbb) but only works for Ollama/Anthropic API backends where cranium manages the tool loop. For Claude Code backend (`manages_tool_loop? -> true`), CC never sees cranium's tool definitions.

MCP is the proper extensibility mechanism. Shape:
1. Cranium exposes MCP server with meta-tools
2. CC launch includes `--mcp-server` pointing to cranium's endpoint  
3. Tool calls route to cranium's internal logic (clear_epoch, etc.)

This also sets up cleanly for future meta-tools without prompt hacks.
